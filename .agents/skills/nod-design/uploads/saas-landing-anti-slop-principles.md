# 끌어당기는 SaaS 랜딩 페이지 설계 원칙

Damien Hirst — Worldview Timeline (https://hirst-fame-argorithm.vercel.app/) 리버스 엔지니어링에서 도출한 디자인 원칙과, AI 생성 랜딩(Claude Design 등)의 slop을 제거하기 위한 실행 지침.

- 작성일: 2026-09-13
- 동반 문서: `hirst-fame-algorithm-scroll-teardown.md` (기술 구현 분석)

---

## 0. 결론 먼저

기술(Lenis, sticky pin, 비디오 스크러빙)은 마지막 10%다. Hirst 페이지가 끌어당기는 이유는 훨씬 앞단에 있다.

**우선순위: 주장(카피) > 타이포그래피 > 색의 면적 절제 > 시그니처 모션 1개 > 디테일**

상위 3개가 안 되면 Lenis를 붙여도 slop이고, 상위 3개가 되면 모션 없이도 끌어당긴다. 기준은 하나다. **JS를 전부 꺼도 여전히 좋아 보이는가.**

---

## 1. 진단: AI slop 랜딩은 왜 매력이 없는가

AI 디자인 도구가 제약 없이 뽑는 랜딩은 거의 항상 같은 조합이다.

| 영역 | slop 패턴 |
|---|---|
| 배경 | 보라/파랑 그라데이션 blob, glassmorphism, 그리드 도트 |
| 카피 | "Ship faster. Build smarter.", "Supercharge your workflow", "Seamless", "10x" |
| 구조 | 히어로 → 로고 벽 → 3열 feature 카드(아이콘 + 두 줄) → 후기 3개 → 가격표 → CTA |
| 형태 | 모든 모서리 `rounded-xl`, 모든 카드에 shadow, 모든 섹션 좌우 대칭 `max-w-6xl mx-auto` |
| 타이포 | Inter 단일, h1 48px / p 18px 수준의 밋밋한 대비 |
| 모션 | 요소마다 순차 fade-up, hover 시 살짝 떠오르는 카드 |
| 색 | 강조색을 버튼, 아이콘, 배지, blob, 링크에 전부 살포 |

개별 요소가 못생겨서가 아니다. **"이 회사만이 할 수 있는 말"이 하나도 없어서** 수천 개 사이트의 평균값이 되고, 뇌가 0.3초 만에 "본 적 있음"으로 분류하고 스크롤을 넘긴다. Hirst 페이지는 그 반대다. 첫 화면에서 "이건 처음 보는데?"가 된다.

## 2. Hirst 페이지에서 실제로 작동하는 것

### 2-1. 논지(thesis)가 하나 있다

"HOW DID HE BECOME THE SYSTEM?" 이 문장이 페이지 전체를 지배한다. 그 아래 DEATH → PRICE → GRID → BURN → INDEX 다섯 챕터가 논증이고, 마지막 트렌드 그래프가 증거다. 랜딩이 아니라 **에세이 구조**다.

SaaS 치환: "우리 제품은 A, B, C 기능이 있다"가 아니라 **"이 문제는 원래 이렇게 풀면 안 됐다"**는 하나의 주장이 필요하다.

- Linear: "Issue tracking you'll enjoy using" (이슈 트래커는 원래 고통스럽다는 전제를 뒤집음)
- Cursor: "The AI Code Editor" (에디터 카테고리 자체를 재정의)
- Hirst: "그는 더 이상 작가가 아니다. 그가 시스템이다."

주장이 없으면 어떤 디자인도 slop이 된다. **디자인 이전에 카피 문제다.**

### 2-2. 타이포그래피가 곧 디자인이다

Hirst의 조합: `Cinzel 900`(대문자 세리프 디스플레이) + `IM Fell English`(18세기 활판) + `Inter`(본문). 히어로 제목은 TextFit으로 화면 폭을 꽉 채우고, 캡션은 `0.66rem` + `letterSpacing 0.32em` 대문자로 극단적으로 작게 쓴다. 이 **크기 대비**만으로 편집 디자인이 된다.

실행:
- 디스플레이 서체 1개 + 본문 서체 1개. 디스플레이는 성격이 뚜렷한 것(세리프, 모노, 컨덴스드, 그로테스크 등). Inter만으로는 무조건 평균값이 된다.
- 제목은 뷰포트 기준 `clamp(3rem, 9vw, 12rem)` 수준으로 과감하게, 캡션은 극단적으로 작게. **중간 크기를 없앤다.**
- `font-variant-numeric: tabular-nums`, `letter-spacing`, `line-height 0.98`, 대문자 캡션 같은 디테일이 "손이 간 느낌"을 만든다.

### 2-3. 색의 면적을 뺀다 (→ 3장에서 브랜드 컬러 있는 경우 상세)

Hirst: `#0A0A0A` 배경 + 오프화이트 + 강조색 `#E63946` 하나(2008년 피크 한 곳에만). 그라데이션 0, 그림자 0, 둥근 모서리 0, 구분선은 `1px rgba(255,255,255,0.14)` 헤어라인.

강조색을 한 곳에만 쓰니 그 한 점이 눈에 박힌다. **색이 2개면 위계가 생기고 5개면 위계가 사라진다.**

### 2-4. 시그니처 순간은 하나면 된다

Hirst의 모션은 실질적으로 둘이다. 스크롤 스크러빙 비디오, 가로 패닝 그래프. 요소별 fade-in은 없다. 그리고 둘 다 **스크롤에 1:1로 묶여 사용자가 제어권을 가진다.** 자동 재생 애니메이션은 광고처럼 느껴지고, 내 스크롤에 반응하는 애니메이션은 조작감을 준다.

slop은 20개의 약한 순간(카드 fade-up)을 만든다. 1개의 강한 순간이 낫다. SaaS라면 **제품의 핵심 동작 하나를 스크롤 스크러빙으로** 보여주는 것(커서가 코드를 고치는 과정, 대시보드가 채워지는 과정)이 feature 카드 12개보다 강하다.

### 2-5. 구체성이 신뢰다

Hirst 텍스트: "5만 파운드", "8,601개의 다이아몬드", "4,851점 소각", "46만 3천 명". 데이터셋 코드에 `caveats`, `verified: true`, `excludedFromStats`까지 남겨두었다. **숫자가 구체적일수록 페이지가 진짜처럼 느껴진다.**

slop: "10x faster", "Trusted by thousands", "Enterprise-grade security". 전부 검증 불가능한 형용사.

실행: 실제 제품 스크린샷(목업 말고), 실제 고객 이름과 숫자, 실제 latency/비용 수치. **없으면 그 섹션을 뺀다.** 빈 자리를 형용사로 채우는 순간 slop이 된다.

### 2-6. 비대칭과 여백

챕터 카드는 가로로 흐르고, 그래프는 화면 폭의 몇 배이고, 단어는 서로 다른 속도로 움직인다. 격자를 의도적으로 깬다. slop은 모든 것이 중앙 정렬 3열 그리드다. 콘텐츠를 한쪽에 몰고 반대편을 비우기만 해도 긴장감이 생긴다.

### 2-7. 디테일이 "사람 손" 신호를 보낸다

- SVG `feTurbulence` 필터로 텍스트에 잉크 번짐 질감 (텍스처 이미지 없이)
- 피크 마커 히트박스를 180px 투명 rect로 확장 (hover 안정성)
- 로딩 화면이 실제 mp4 다운로드 진행률을 표시
- 데이터 출처와 채택하지 않은 수치를 코드에 명시

이런 것들은 사용자가 의식적으로 인지하지 못해도 "대충 만든 게 아니다"라는 신호로 누적된다.

## 3. 브랜드 컬러와 스타일 컨셉이 이미 정해져 있을 때

### 3-1. "색을 뺀다"의 정확한 의미

색을 쓰지 말라는 게 아니라 **면적을 빼라**는 뜻이다. 브랜드 컬러가 정해져 있으면 오히려 유리하다. 결정할 것이 줄어든다.

문제는 브랜드 컬러를 **어디에** 쓰느냐가 아니라 **얼마나 넓게** 쓰느냐다.

| 사용 방식 | 결과 |
|---|---|
| 배경 전체, 그라데이션, 카드 채우기, blob | slop. 채도 높은 색을 넓은 면적에 깔면 값싸 보인다 |
| 점, 선, 한 단어, CTA 버튼 하나, 그래프의 피크 하나 | 브랜드로 각인된다 |

강한 브랜드 컬러를 가진 회사들의 랜딩 실제 비율:

- **Stripe** (보라): 페이지의 90% 이상이 흰/검. 보라는 히어로 그라데이션 한 곳과 링크에만.
- **Spotify** (초록 `#1DB954`): 검정 배경. 초록은 CTA 버튼과 로고에만.
- **Linear** (보라): 거의 보이지 않는다. 다크 중립 위에 아주 드물게.
- **Notion**: 사실상 흑백. 브랜드 컬러는 일러스트 안에서만.
- **Hirst**: 검정 + 오프화이트. 빨강 `#E63946`은 페이지 전체에서 한 점.

### 3-2. 브랜드 컬러 예산(budget) 규칙

브랜드 컬러를 "예산"처럼 취급한다.

- 첫 화면(above the fold): **최대 1곳** (보통 CTA 버튼 또는 제목의 한 단어)
- 페이지 전체: **3~5곳**
- 나머지 95%: 중립색 (검정/오프화이트/회색 계열)

일반적으로 알려진 60/30/10 비율은 랜딩에서는 너무 많다. **90(중립 배경) / 8(중립 텍스트·선) / 2(브랜드 컬러)** 정도가 적정.

### 3-3. 브랜드 팔레트에 색이 여러 개일 때

브랜드 가이드에 primary, secondary, tertiary가 있어도 **랜딩에서는 primary 하나만** 꺼낸다. 나머지는 제품 UI 스크린샷이나 일러스트 안에서만 자연스럽게 등장하게 둔다.

브랜드 가이드는 보통 "사용 가능한 팔레트"이지 "모두 사용하라"가 아니다. 가이드가 "primary 버튼 색"과 로고 정도만 정한 것이라면 랜딩 디자인에는 거의 제약이 없다.

예외: 두 색의 **조합 자체**가 정체성인 경우(듀오톤 브랜드). 이때는 그 조합을 시그니처 모션이나 히어로 비주얼 **하나에 집중**시키고, 배경과 타이포는 여전히 중립으로 간다.

### 3-4. 중립색을 브랜드 쪽으로 살짝 기울인다

"브랜드 느낌"은 강조색 면적이 아니라 **중립색의 온도**로 남길 수 있다.

```
브랜드 보라 → 배경 #0B0A10 (보라끼 검정), 텍스트 #ECEAF2 (보라끼 오프화이트)
브랜드 초록 → 배경 #0A0D0B, 텍스트 #E9EFEA
브랜드 주황 → 배경 #0F0C0A, 텍스트 #F2EDE8
```

순수 `#000`/`#FFF` 대신 브랜드 색상을 2~4% 섞은 중립을 쓰면 강조색을 거의 안 써도 페이지 전체가 브랜드 톤을 띤다. Hirst도 `#0A0A0A`이지 `#000`이 아니다.

### 3-5. 다크 vs 라이트 결정 기준

브랜드 컬러가 가장 잘 사는 배경을 고른다.

- 채도 높고 밝은 색(네온 초록, 민트, 노랑, 시안): **다크 배경**. 흰 위에서는 번지고 읽히지 않는다.
- 진하고 무거운 색(네이비, 딥 퍼플, 버건디): **라이트 배경**. 검정 위에서는 묻힌다.
- 중간 채도(코랄, 스카이블루): 둘 다 가능. 제품 UI가 다크면 다크로 맞춘다.

### 3-6. 스타일 컨셉이 정해져 있을 때

컨셉이 있는 것은 유리하다. 단, 컨셉은 형용사 상태로는 제약이 안 된다. **"무엇을 하지 않는가"로 번역**해야 실제 디자인 결정이 된다.

| 컨셉 (형용사) | 타이포 | 형태 | 모션 | 하지 않는 것 |
|---|---|---|---|---|
| 정밀함 / 엔지니어링 | 모노스페이스 디스플레이, tabular-nums | 직각, 1px 헤어라인, 그리드 노출 | 선형 이징, 스냅 | 둥근 모서리, 그림자, 부드러운 곡선 |
| 따뜻함 / 사람 중심 | 세리프 디스플레이, 넉넉한 line-height | 오프화이트, 약간의 라운드 | 느린 ease-out, 페이드 | 네온색, 다크 모드, 기계적 모션 |
| 럭셔리 / 에디토리얼 | 하이컨트라스트 세리프, 극단적 크기 대비 | 넓은 여백, 비대칭, 대문자 캡션 | 스크롤 연동 패럴럭스 | 카드 UI, 아이콘, 3열 그리드 |
| 속도 / 개발자 도구 | 그로테스크 산세리프, 컨덴스드 | 다크, 코드 블록 노출 | 즉각적, 짧은 duration | 일러스트, 마스코트, 장식 |
| 놀이 / 크리에이티브 | 디스플레이 서체 2개 혼용 허용 | 강한 색 대비, 오브젝트 겹침 | 바운스, 드래그 인터랙션 | 기업형 톤, 회색 계열 |

이 표에서 자기 컨셉의 행을 고르고, **"하지 않는 것" 열을 AI 프롬프트의 금지 목록에 그대로 넣는다.**

### 3-7. 검증 테스트

1. **흑백 테스트**: 페이지를 grayscale로 바꿔도 위계와 시선 흐름이 남는가. 남으면 색은 덤이고, 페이지가 무너지면 색에 의존한 것이다.
2. **브랜드 컬러 카운트**: 첫 화면에서 브랜드 컬러가 쓰인 곳을 센다. 3곳 이상이면 줄인다.
3. **면적 테스트**: 브랜드 컬러가 화면 면적의 5%를 넘는 섹션이 있는가. 있으면 그 섹션이 slop의 원인일 확률이 높다.

## 4. SaaS 랜딩만의 제약: 명료함과 서사의 균형

Hirst는 전환 목표가 없는 에세이라 첫 화면에 설명이 없어도 된다. SaaS는 **첫 화면에서 "뭐 하는 제품인지" 5초 안에** 알려야 한다.

균형:

```
[히어로]  주장이 담긴 제목 한 문장
          + 뭐 하는 제품인지 한 줄 (부제)
          + CTA 하나 (브랜드 컬러 사용처 1)
          → 여기까지는 명료함 우선

[본문]    Hirst처럼 서사 구조 + 시그니처 모션 1개
          → 여기서부터 끌어당김
```

Linear, Vercel, Resend, Raycast 랜딩이 이 균형의 참고 사례. 전부 색 2~3개, 타이포 중심, 모션 절제.

## 5. AI 디자인 도구(Claude Design 등) 프롬프트 제약

slop이 나온 것은 도구가 제약 없이 "평균"을 뽑았기 때문이다. 아래를 프롬프트에 명시한다.

### 5-1. 금지 목록

```
- 그라데이션 배경, blob, glassmorphism, 도트 그리드 배경 금지
- 카드 그림자, rounded-xl 이상의 둥근 모서리 금지
- 3열 feature 카드 그리드 금지
- 아이콘 + 짧은 문장 조합 금지
- 다음 단어 금지: Ship faster, Supercharge, Seamless, Powerful, Effortless,
  Revolutionize, Unlock, 10x, Trusted by thousands, Enterprise-grade
- 요소별 순차 fade-up / slide-in 애니메이션 금지
- 브랜드 컬러 외 유채색 사용 금지
- 브랜드 컬러를 배경이나 넓은 면적에 사용 금지
- 모든 섹션 중앙 정렬 금지
- 검증 불가능한 숫자/형용사 금지
```

### 5-2. 요구 목록

```
- 페이지 전체를 관통하는 주장 한 문장을 먼저 작성하고,
  모든 섹션이 그 주장을 증명하는 순서로 구성
- 디스플레이 서체 1개 (세리프/모노/컨덴스드 중 성격 있는 것) + 본문 서체 1개
- h1은 clamp(3rem, 9vw, 12rem) 수준의 뷰포트 기준 크기
- 캡션은 대문자 + letter-spacing 0.2em 이상 + 0.7rem 이하
- 배경: 브랜드 컬러를 2~4% 섞은 중립 다크 또는 라이트
- 브랜드 컬러 사용처: 첫 화면 1곳, 전체 3~5곳으로 제한하고 위치를 명시
- 실제 제품 화면 1개를 스크롤 연동 시그니처 모션으로, 나머지 모션 없음
- 모든 숫자는 실제값. 없으면 해당 섹션 삭제
- 최소 한 섹션은 비대칭 레이아웃 (콘텐츠 한쪽 배치 + 반대편 여백)
- 구분선은 1px 헤어라인, 투명도 10~15%
- [컨셉 행의 "하지 않는 것" 열 붙여넣기]
```

### 5-3. 결과 검토 체크리스트

- [ ] 첫 화면 제목이 "주장"인가, "기능 설명"인가
- [ ] 이 제목을 경쟁사 이름으로 바꿔도 말이 되는가 (되면 실패)
- [ ] 폰트가 Inter/Roboto/system-ui 하나뿐인가
- [ ] 제목과 캡션의 크기 비율이 10배 이상인가
- [ ] 그라데이션, blob, glassmorphism이 있는가
- [ ] 첫 화면에 브랜드 컬러가 3곳 이상인가
- [ ] 3열 카드 그리드가 있는가
- [ ] 모션이 3개 이상인가
- [ ] "Trusted by", "10x", "Seamless"가 있는가
- [ ] 흑백으로 바꿔도 위계가 남는가
- [ ] JS를 꺼도 좋아 보이는가
